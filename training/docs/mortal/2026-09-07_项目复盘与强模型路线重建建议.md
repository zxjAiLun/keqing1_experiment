# 项目复盘与强模型路线重建建议

日期：2026-09-07。性质：T1 收口复核、历史证据综合、下一阶段提案；不是新训练授权或预注册合同。

## 1. 总判断

项目已经建立了较严格的训练、评测和拒绝晋级流程，但尚未建立一条稳定产出强于 K0 的训练路线。当前 registry 共 27 条记录，包含模型、工程、机制审计与训练实验，不能理解为 27 次完整从零训练。唯一正式模型仍是 K0@70000，K1=null。

目前最值得纠正的前提是：

1. 克隆 Mortal 代码、使用示例超参数，不等于复现官方服务 4.1 的完整训练配方。
2. K0 与 external 不只是训练步数不同，它们的网络规模也不同。
3. 高损失不自动等于没有学习；辅助顺位 CE、GRP CE、行为 CQL、Q 回归是不同指标。
4. 多轮小规模续训未晋级，限定的是这些具体协议，不能推出 Mortal 无法训练、所有在线 RL 无效，或 K0 已达到架构上限。
5. 下一步应先补齐初始训练的可复现性与学习曲线，再决定从零重训或继续 K0；不再自动追加一种 400-step 正则化变体。

## 4. 70K 到底是什么；external 又是什么

本次用已有 Windows Python 和 `torch.load(..., weights_only=True, map_location='cpu')` 直接读取两份 checkpoint 元数据及张量尺寸，没有下载模型。

| 项目 | K0 / 70K | external |
| --- | --- | --- |
| 文件 | `mortal_default_70k_promoted_candidate.pth` | `external_mortal_20240308_best_min.pth` |
| checkpoint steps | 70000 | 未保存 |
| observation/network contract version | 4 | 4 |
| ResNet | 192 channels × 40 blocks | 256 channels × 54 blocks |
| Brain+DQN 参数元素数，排除 BN buffers | 10,835,631 | 23,711,663 |
| 训练配方、optimizer 元数据 | config/optimizer/scheduler/aux 等存在 | 只有 mortal/current_dqn 与最小网络 config |
| 官方 4.1B/C 身份 | 不是这种命名 | 无元数据证明 |

external 推理网络规模约为 K0 的 2.19 倍。这是可确认的差异，不是“增大模型一定能解决”的因果证明；文件日期也不能证明实际训练日期或官方来源。

K0 配置保存 `batch_size=512`、`opt_step_every=1`、LR=1e-4、CQL=5、next-rank=0.2、gamma=1、pts=[6,4,2,0]、augmentation=false、offline 模式。因此 70K 在这个计步规则下是 70000 次 optimizer 更新，不是 70000 局。按每步完整 batch 计算是约 3584 万行暴露量，不是 3584 万个独立局面；去重、重复轮次、历史重启和最初初始化还需要原始数据链确认。

旧仓库 `3967c06:docs/mortal/reward_pt_experiment_report_2026_05.md` 明确记载：K0 是 R0/default 分支，由 65000-step 母体继续到 70000，使用旧 GRP；`default_mainline_progress_2026_05.md` 记载 80K 未晋级。旧有限 runner `e8e29b4:scripts/run_mortal_dqn_offline.py` 的 Q 目标为折扣后的 kyoku reward，含 DQN/CQL/next-rank 三项损失。

因此必须区分：K0 的 GRP delta-Pt 路线，与后来 M0 将半庄最终顺位回报分配给每个决策的 final_rank_mc 路线。不能用当前代码的默认 reward 倒推 5 月 K0。

现存 K0 的 `best_perf={avg_rank:4.0,avg_pt:-135.0}` 与旧 runner 初始化哨兵一致，不能当作它实际打过的战绩。最初 0→65K 的完整初始化链、训练文件 manifest、实际覆盖率和分项损失曲线未在本次定位齐全；历史 runbook 所述约 10.6 万转换文件不等于已证实全部被 K0 消费。原始 tensorboard 曲线没有找到，不能声称已重新观察到其 CE 长期平台。

## 5. “对 external 只有 2.6”应如何解释

如果 2.6 指平均顺位，相对对称同强条件下的 2.5 确实是落后；但数值不是 Elo，也没有脱离对手阵容、规则、座位和样本量的固定强度含义。

本次定位到 `v3_final_rank_mc_2026_07.md` 中：

- 250 局四模型混桌 screen：K0=2.608，external=2.500。
- 后续 1000 seat-hanchans/模型的平衡 league：K0=2.484，external=2.449。

它们不是同一测试，不能直接拼接成稳定差距或宣称后者否定前者。更不能把这种混桌结果直接与官方 1v3 duplicate 表比较。该历史文档部分统计还早于 ReachAccepted 修复；这里仅用于识别用户所指口径，正式差距应使用修复后的原始日志重算。本次没有复算这些历史 league。

后续独立基准应同时保留固定 external 的 1v3、反向 1v3，以及冻结多模型池：前者测特定对手差距，后者防止只适应某个对手。相同 seed 下的四个座位轮换需按 seed set 聚类统计，不能当作四个完全独立样本。冻结主指标 Pt、次指标平均顺位，并明确区别训练 reward 的 [6,4,2,0] 与评测 Pt 的 [90,45,0,-135]。

## 6. 运气、交叉熵与训练为什么不变强

你的直觉有一部分正确：正确决策可能输，错误决策可能赢；把一场半庄的结果赋给许多决策会带来很强的噪声与信用分配困难。但强化学习要估计的是条件期望，不是保证每一局的输赢都可预测。随机性提高所需样本和估计方差，不意味着权重原则上无法收敛。

当前主线的简化损失为：

`L = 0.5*MSE(Q(s,a_behavior), G) + 5*(logsumexp(Q_legal)-Q(s,a_behavior)) + 0.2*CE(next_rank, label)`

其中：

| 指标 | 实际学习对象 | 应如何判断 |
| --- | --- | --- |
| Q / DQN MSE | 回报标量；M0 的 G 是 [+3,+1,-1,-3] 最终顺位回报 | 比较独立集常数/状态基线、校准与分阶段残差，不要求归零 |
| CQL | 本实现数值等价于用 masked Q 做 logits 的行为动作 NLL，但 Q 本身并非校准概率 | 取决于动作分布和合法动作数，不能统一用 log(46) 当基线 |
| next-rank CE | 下一局边界的自身顺位，4 类辅助任务 | 均匀基线 log(4)≈1.386；更应对比当前顺位保持/经验先验基线 |
| GRP CE / NLL | 四家最终名次排列，24 类 | 均匀基线 log(24)≈3.178，不可与 4 类 CE 混比 |

实际证据：7 月项目 GRP v1 的 validation NLL 从 3.1053 降到 2.6700，独立 holdout 为 2.6145；这是可学习信号，不是“2.6 因而完全没收敛”。5 月旧 GRP 跨域审计的 CE 也约 2.57–2.62，但没有支持“80K 失败主要由 GRP 回报方差变坏造成”。这两代 GRP 不是同一个 checkpoint。

已有 M0 learnability audit：938158 个决策，终局目标标准差约 2.188；K0 Q 与目标相关系数约 .259，线性解释量约 6%–7%；6000 半庄中约 89% 的 external 动作本来就与 K0 贪心动作一致。它们提示新策略信号有限、价值标量噪声较大，但低 R²和粗状态桶方差不是条件熵或不可约误差的精确估计，不能证明网络已到上限。

更关键的是：external 生成的牌谱主要提供它实际选过的动作及那次对局结果，不自动提供“同一状态所有其他合法动作的真实期望收益”。这不是完整教师价值函数的蒸馏。CQL 行为偏好、回报拟合、共享表示和策略分布变化相互作用，loss 变低可以主要来自标量校准或辅助预测变好，而非关键动作排序变好。S1 和 T1 已提供这种“机制/辅助指标改善不等于强度改善”的直接实例。

所以不建议把下一阶段写成“去掉运气、让 CE 归零”，也不应以未查证曲线为由立即更换损失函数。

## 7. 官方 4.1B / 4.1C：公开事实与不知道的部分

本次检索官方仓库、官方文档与作者说明：

- [官方示例配置](https://raw.githubusercontent.com/Equim-chan/Mortal/main/mortal/config.example.toml) 明确说明很多数值仅是类型占位示例，往往非最优，需要调整。不能把示例称为官方最佳训练配方。
- [官方服务历史](https://mjai.ekyu.moe/) 记载 4.1 系列于 2024-08-31 发布；服务版本标签不等于 checkpoint 内 observation version=4。
- [官方强度页](https://mortal.ekyu.moe/perf/strength.html) 使用 1v3 duplicate 协议；4.1b 和 4.1c 对 4.0 的各百万挑战者半庄数据分别为平均顺位 2.493512 / 2.485211、Pt +0.377460 / +0.254205。这也显示平均顺位更好不一定意味着该 Pt 目标更好，不能据字母顺序认定全面更强。
- [作者模型发布说明](https://gist.github.com/Equim-chan/cf3f01735d5d98f1e7be02e94b288c56) 的 2022-08-19 更新说当时无发布训练模型计划；当前 README 仍链接该说明。这不是完整 4.1 训练记录。

在本次能够核验的官方材料中，没有定位到 4.1b/c 完整数据 manifest、初始化母体 SHA、各训练阶段步数与优化超参数。不能负责任地编造“基于某某 checkpoint、加某辅助头、训练多少步就得到 4.1c”。公开代码足以研究与实现 Mortal 路线，不意味着公开了服务每代模型的端到端复现包。

## 8. 下一阶段开发方案：先明确缺口，再花训练预算

建议路线名称暂记“强模型训练基线重建”，不写入 registry 的 next_experiment，不沿用 T1/F3 等冻结身份。本次只提出方案。

### 阶段 A：训练来源与学习曲线审计，无 optimizer 更新

交付物应是一份机器可读 K0 reproduction manifest，加一份独立验证诊断。尽量使用现存文件，不生成新牌谱，不下载环境。

1. 追回 0→65K→70K 的初始化、旧 runner/原生库 revision、旧 GRP、数据来源/水平/规则、去重划分、重启次数和实际行暴露量；缺失明确记 unknown，不补造。
2. 从原始事件日志区分 Q/CQL/next-rank/GRP 曲线；如果曲线缺失，不能用重新跑一次冒充原曲线。
3. 核对旧 reward 与现有 reward 的实际张量、量纲、gamma、终局映射、优化器步号和 BN 推理模式；使用固定合法样本做数值对照，不修改历史训练结果。
4. 在按半庄分离、无泄漏的保留集上，报告分项 loss 相对基线、行为动作匹配、合法动作数、分阶段/副露窗口指标。使用冻结探针，不按评测输赢挑选“坏动作”。
5. 形成预算依据：已测吞吐、GPU 显存、读盘、实际可用数据。不能按 step 数推断 epochs 或未经测量承诺耗时。

结束条件：能够指出主要缺口是训练链未复现、拟合/泛化问题、样本支持不足，还是没有足够诊断证据。已有 7 月 learnability audit 不再机械重做；只补 0→70K 来源与独立验证的缺失部分。若关键旧资产在另一系统，列出准确文件再请用户协助，不能擅自启动 WSL。

### 阶段 B：新的独立训练身份，一条从零学习曲线基线

这是当前优先候选，不是保证更强的承诺；需阶段 A 结果、数据可用性与资源预算确认后预注册。

- 先固定 Mortal/libriichi 表示与 46 动作契约，不重写环境或前端。
- 首个从零基线优先保持 K0 的 192×40 架构，以隔离训练链能否复现；不是直接照 external 容量放大，更不同时扫大小/LR/CQL/奖励。
- 训练数据、目标、优化器、augmentation 和总预算逐项写明理由。若旧初始语料缺失，必须承认是新基线而不是 K0 精确复现。
- 新训练前增加小样本可拟合性 sanity test，区分管线错误与完整分布难学；它只验证工程，不用于强度晋级。
- 预注册固定训练检查点，报告训练与独立验证学习曲线、有效样本暴露量。检查点筛选集和最终确认集分开，防止反复试到好 seed。
- 用学习曲线决定是否值得完成既定预算，不能因第 400 步不强就断言从零路线失败，也不能失利后无限延长。数值异常、数据泄漏、学习曲线失败的停止规则事先冻结。

如果 A 已证明旧基线具有完整可靠曲线且预算内无重新训练价值，就不为了“从零”而从零；应先预注册另一个有诊断支撑的单变量研究。这是决策门，不是同时开多个实验。

### 阶段 C：独立强度确认，再考虑在线持续改进

- 先用现有日志估算目标效果量下所需样本量，按明确预算冻结最终评测局数；不要把“每轮都 3000 局”当作万能统计标准，也不要追加旧 T1 对局。
- 候选与 K0 在相同 external 对手、相同墙与轮换座位下分别测试，保留反向与固定池外部有效性检查；统计单位是 seed set，多个训练 seed 另作分层。
- 以预注册强度指标为晋级条件。学习曲线、辅助头精度、教师一致率只作诊断。
