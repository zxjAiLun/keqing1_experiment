## 2. 为什么 audit-v1 失去判决资格

audit-v1 对同一 shard 给出 `FAIL`（`79f39c79…` / `9fd32381…`，历史保留）：

- `q_recompute = 18281`（几乎每个 eligible event 的 top1/top2/margin 与 offline 重算不一致）；
- context-set 偏移：missing / extra = 77 / 77，loader_mapping = 11。

关键证据是**对照实验**：在完全相同的 frozen runtime、相同 K0、相同 q=512 口径下，authoritative 25h smoke 复现了同型失败签名（`q_recompute ≈ 3×703`、missing/extra = 5/5、相同 violation 类别、数值分布 median ~5e-5、尾部 max ~7.0）。因此：

1. offline `GameplayLoader → records_from_game → brain/dqn` 的批量 Q 重算不是 generation-time arena 推理的可互换数值 oracle；`rel_tol=1e-5/abs_tol=1e-6` 的 Q 相等性没有判决资格。
2. audit-v1 用 loader 行序 + `primary_row_flags()` 自行推导每 kyoku 的 decision_index，与 native arena 场景序列存在系统性偏差——arena 每轮只咨询一次模型、`decision_index` 归 arena 所有，且 arena 从不咨询立直后强制打牌（D3 engine 的 `not_eligible_finite_action_count == 0`），而 loader 会跳过被他人荣和抢先的反应行。

结论：audit-v1 的 gate verdict 被判定无效（superseded），不是因为 generation 有问题被“修复”。

## 3. auditor-v2 如何重建 native-scene correspondence

auditor-v2（`cf9bb86`，仅审计侧改动；generation contract 未动）以确定性方式重建 arena 场景序列：

- 用与 arena 共享的 `libriichi.state.PlayerState` 逐事件重放 mjai log，按 `can_act` 生成场景流；
- 精确镜像 `gameplay.rs` 的 label 逻辑（含 aka/chi 类型/荣和/过牌），loader 行按 label 匹配消耗；
- 立直后单合法动作的强制打牌行标记为非 arena 场景（arena 从不咨询）；
- 每个 loader 行获得真实的 arena `(kyoku, decision_index)`。
