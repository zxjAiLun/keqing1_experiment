### 3.3 C1 raw-log metadata schema

只读扫描了 C1 24 个 shard 的全部 6000 个 raw logs。目标模型的 decision metadata 具有：

```text
event.meta.q_values   compact legal-action Q values
event.meta.mask_bits  46-action legal mask bitset
event.meta.is_greedy
event.meta.batch_size
event.meta.eval_time_ns
```

已核验的结构事实：

- 每个目标模型在每个 raw log 中都存在带 `q_values` 的 decision row；
- `len(q_values) == popcount(mask_bits)`；
- 全量扫描中没有发现 q/mask 长度错误或非有限 legal Q；
- q 值是按合法 action 压缩保存的，未来实现必须按冻结 native action index 恢复为 46 维向量；
- 非法 action 的 Q 在模型输出阶段被 mask 成 `-inf`，raw log 不保存一个可用于比较的“illegal baseline”。

因此，C2 的 H1/H2/H3 可以从既有 C1 raw logs 读取 Q/mask/行为 action；但“illegal action suppression”只能作为结构性 mask gate，不能作为独立 calibration effect 指标。

## 4. 数据单位、身份与 pairing

### 4.1 Cell 定义

只分析：

```text
route       ∈ {M0, D1}
condition   ∈ {CURRENT, CQL_OFF}
seed        ∈ {20260806, 20260807, 20260808}
```

从每个 C1 raw log 中只保留其 `names` 中对应的 `M0_*` 或 `D1_*` seat；固定 `70k` 与 `ext_mortal` seat 不进入 C2 metric rows。包含 metadata 的 action event 类型全部保留，包括 `dahai`、`chi`、`pon`、`reach`、`ankan`、`kakan`、`daiminkan` 等；不得只保留容易解析的 discard rows 来改变 estimand。

每个 decision row 的 frozen identity 为：

```text
(condition,
 training_seed,
 hanchan_seed,
 seed_key,
 source_log_sha256,
 model_label,
 event_ordinal)
```

`event_ordinal` 按 raw JSONL 顺序定义。行为 action 必须由现有 native action/event mapping 解码，并且必须落在 `mask_bits` 的合法坐标内；不能根据 q 值的排序反推行为 action。

### 4.2 Target 与 C1 pairing

C1 training objective 的 rank target 固定为：

```text
reward.mode = final_rank_mc
y ∈ [6, 4, 2, 0]
```

这里的 `[6,4,2,0]` 是训练 objective 的 target，不得误用 evaluation rank points `[90,45,0,-135]`。未来实现使用同一个 raw log 的最终 native rank，把对应 route model seat 映射到 `y`。

CURRENT/OFF hanchan pairing 只允许使用 C1 已核验的 key：

```text
(training_seed, hanchan_seed, seed_key, role_order, role_to_seat)
```

C1 formal summary 已核验 3000 个唯一 paired hanchans，且每个 pair 保存了 CURRENT/OFF source-log SHA。C2 的 row-level metric 使用 hanchan cluster 作为统计单位；不能把 CURRENT 与 CQL_OFF 的 decision rows 假设为逐 state 对齐。

## 5. 共同统计约定

对任意一个 metric `m`，先在每个 hanchan 内计算 cell-level summary，再在 training seed 内对 1000 个 hanchan 等权平均。定义：

```text
Δ_R(m) = m(R, CQL_OFF) - m(R, CURRENT)
I(m)   = Δ_D1(m) - Δ_M0(m)
```

`I(m)` 是机制 metric 的 route × intervention contrast；它不是 C1 的 rank-level DID，也不替代 C1 result。

固定 bootstrap：

```text
reps       = 5000
seed       = 20260818
confidence = 95%
```

bootstrap 方案：

1. 在每个 training seed 内，对 1000 个 paired hanchan key 有放回抽样；
2. 同一次 replicate 对 M0/D1、CURRENT/CQL_OFF 四个对应 cell 使用同一组 hanchan multiplicity；
3. 先得到三个 training-seed level 的 `I(m)`，再对三个 seed 等权平均；
4. CI 使用预先固定的 percentile `[2.5%, 97.5%]`；
5. 缺失 raw log、缺失 metadata、pair key 不一致、目标 action 非法或 target 无法恢复时，整个 metric gate FAIL，不能通过删除异常 rows 产生 provisional readout。

正式结果只报告 CI 和冻结的 machine vote，不做未预注册的 p-value、阈值搜索或 metric substitution。

## 6. Mechanism H1：action support / over-constraint

### H1 hypothesis

D1/K0-like route 的 behavior action support 更集中时，CQL 对合法 action preference 的额外约束可能过强。移除 CQL 后，D1 的 decision-level support signature 相对于 M0 的变化应更明显。

这是对冻结 evaluation trajectories 的机制一致性检查，不声称直接观察到了 72k training replay 的原始 action support。

### H1 metrics

对每个 decision row：

```text
legal_count = popcount(mask_bits)
```

当 legal action 数至少为 2 时，定义：

```text
q_behavior = Q(s, a_behavior)
q_alt      = max { Q(s,a) : a legal, a != a_behavior }
margin     = q_behavior - q_alt
agreement  = 1[argmax(Q_legal) == a_behavior]
```

另外按 hanchan 汇总 decoded behavior action 的经验分布，报告：

```text
H_behavior = -Σ_a p(a) log p(a)
effective_action_count = exp(H_behavior)
```

`legal_count`、`H_behavior` 和 `effective_action_count` 都必须报告。由于 `effective_action_count` 是 `H_behavior` 的单调变换，它们只算一个 entropy/support family，不重复投票。

### H1 machine rule

H1 的三个预先指定方向是：

```text
I(margin)                  > 0
I(agreement)               > 0
I(H_behavior)              > 0
```

即 D1 的 `CQL_OFF - CURRENT` 相对变化应大于 M0，且方向符合“移除约束后 support/preference 更开放”的预注册解释。三者的 95% CI lower bound 都必须大于 0，才记：

```text
action_support_mechanism_signal
```

`legal_count` 是 mandatory descriptive，不单独改变 H1 vote。若 H1 的任一 primary family 没有 CI 支持，H1 为 false；不允许运行后改用 legal count 替代 margin 或 agreement。

## 7. Mechanism H2：Q calibration

### H2 hypothesis

CQL 在 D1 route 上可能造成 Q scale / legal preference calibration distortion。预期表现为 CURRENT 的 Q magnitude 或 legal spread 被压缩、`Q(s,a_behavior)` 与同一局 final-rank target 的误差更大；CQL_OFF 相对恢复，且 D1 的恢复幅度超过 M0。

### H2 metrics

按 legal Q values 计算：

```text
q_abs_mean       = mean(|Q_legal|)
q_legal_std      = std(Q_legal)
q_legal_range    = max(Q_legal) - min(Q_legal)
target_gap       = Q(s,a_behavior) - y
abs_target_gap   = |target_gap|
```

H2 的三个 metric family 冻结为：

1. **Q scale family**：`q_abs_mean` 和 `q_legal_std` 必须同时显示 D1 的恢复方向；
2. **legal spread family**：`q_legal_range` 显示 D1 的恢复方向；
3. **target-gap family**：`abs_target_gap` 的 D1 恢复方向为减小，即 `I(abs_target_gap) < 0`。

非法 action baseline 不进入 H2 metric，因为 C1 evaluator 在 Q 输出后已把非法坐标 mask 为 `-inf`，raw log 只保存 legal compact Q；它只用于 metadata/mask structural gate。

### H2 machine rule

H2 family vote 采用冻结的 `2/3`：

```text
q_calibration_mechanism_signal
iff at least 2 of the 3 H2 families have the expected CI direction
```

每个 family 的方向都按 `I(m)` 判断，不使用 route 的 absolute strength，不把 D1 的绝对 Q 值直接解释为优于 M0。

## 8. Mechanism H3：gradient interaction

### H3 hypothesis

CQL 可能改变 value signal 与 CQL preference signal 的几何关系。若 D1 route 的 CQL/value conflict 更强，CQL 会更频繁地抵消数据 action 对 Q 的 value correction。

### H3 Q-output decomposition

C2 只计算 46 维 Q-output space 的解析梯度，不运行 autograd，不计算 backbone/parameter gradient，也不计算 optimizer update：

```text
g_value = (Q(s,a_behavior) - y) · one_hot(a_behavior)
g_cql   = λ_diag · (softmax(Q_legal) - one_hot(a_behavior))
```

H3 的 `λ_diag` 固定为：

```text
λ_diag = 5.0
```

这个值在 CURRENT 与 CQL_OFF 两种 checkpoint 上都相同。它表示“在各自冻结 Q surface 上评估同一个 CQL component”的 counterfactual diagnostic；它不把 CQL_OFF checkpoint 的实际训练 objective 改写成 CQL=5。若在 CQL_OFF cell 使用 `λ=0`，`g_cql` 会结构性为零，cosine 也会全部失去定义，因此不得采用该做法。

定义：

```text
cosine = dot(g_value, g_cql) / (||g_value|| · ||g_cql||)
conflict_rate = P(cosine < 0)
```

若任一范数不超过：

```text
GRAD_EPS = 1e-12
```

该 row 不进入 cosine 分布，但必须计入 `cosine_defined_rows`、`cosine_defined_rate`；不能把 undefined 当作 zero conflict。 `g_total = g_value + g_cql` 的 norm、centered preference pressure 和 zero-gradient rate 作为预先指定的 descriptive cross-check。

### H3 machine rule

H3 的主要 contrast 方向固定为：

```text
conflict contrast =
  [conflict_rate(D1, CURRENT) - conflict_rate(D1, CQL_OFF)]
- [conflict_rate(M0, CURRENT) - conflict_rate(M0, CQL_OFF)]
```

主要 contrast 的 95% CI lower bound 必须大于 0；同时 cosine 的 route contrast 必须显示相反方向（D1 的 `CURRENT - CQL_OFF` mean cosine 相对 M0 更低，95% CI upper bound < 0）。两者都满足才记：

```text
gradient_conflict_signal
```

H3 的语义严格限定为 `dL/dQ` component geometry，不等价于既有 K0 report 中的 parameter-gradient / Adam cosine。

## 9. 综合 machine readout

仅在全部 provenance、row identity、pairing、metadata、target 和 defined-row gates PASS 时，使用以下四态：

```text
action_support_mechanism_signal
q_calibration_mechanism_signal
gradient_conflict_signal
multiple_mechanisms
inconclusive
```

综合规则：

```text
H1 + H2 + H3 中 true 的数量 >= 2  → multiple_mechanisms
恰好 1 个 true                   → 对应单一 signal
0 个 true                         → inconclusive
任一硬门禁 FAIL                   → 不发布 mechanism verdict；记录 no_verdict_gates_failed
```

`multiple_mechanisms` 只表示多个预注册诊断 family 同时通过，不能解释为多个独立因果中介已经被证明。

## 10. Hard gates 与 fail-closed 规则

未来 implementation 必须在结果发布前验证：

- C1 formal summary schema、SHA、verdict 和 counts 与本草案第 3 节一致；
- 12 个 target checkpoint 的 path、label、seed、condition 和 SHA 全部匹配 execution-time provenance；
- 24 shard / 6000 raw-log inventory 完整；CURRENT/OFF 的 3000 hanchan pairing exact；
- raw log 的 `start_game.names`、training seed、hanchan seed、seed key、role-to-seat 与 C1 parser 一致；
- 每个 target model 的 metadata row 都能恢复 legal mask、Q vector、behavior action 和 final-rank target；
- q/mask compact encoding 的长度、bit index、action index 和 finite checks 全部通过；
- `CQL_OFF` 的 actual training history 只绑定到 CQL=0 的已完成 checkpoint；H3 的 λ=5 仅为统一 diagnostic；
- bootstrap 的 reps/seed/confidence、hanchan cluster unit 和 paired resampling 未改变；
- 输出目录在运行前不存在，正式运行不能覆盖旧结果；
- formal result 的 source identity、runtime identity、input SHA 和 implementation commit 全部写入结果 provenance；
- 任意硬门禁失败时不发布 provisional mechanism verdict。

单 legal action、zero norm 等数学 undefined 情况只能按本草案已经写明的规则处理并报告 denominator；不能用 post-hoc filtering 改善 signal。
