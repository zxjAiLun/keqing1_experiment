## 研究问题

D1 的纯 K0-view lineage 在三组 B250 评测中稳定劣于 M0。其 `70k greedy agreement` 接近 100%，与“没有足够的有效动作支持”这一机制假设一致，但 D1 同时改变了完整 replay lineage，不能把动作支持不足宣称为唯一因果来源。

D3 要回答的是：

> 在 K0 的低 margin 状态引入受控、可复现的探索，能否形成比纯 K0-view 更有用且不失控的 project-owned replay lineage？

这里的“有用”必须先用 parent-Q 支持、动作语义和行为分布描述；不能把低 margin 自动当成正确探索，也不能把 ext/reviewer/NAGA 当硬标签。

## D3 generation contract v1（已预注册，function smoke 已通过，production 未启动）

本 contract 只冻结一个 recipe，不生成 `p=0.1/0.25/0.5` 网格。D3 生成器实现完成后，必须严格消费以下字段：

1. **唯一探索主体**：只有 `K0_70k` trainable player 使用 exploration policy；其余三家继续使用 D1 相同的冻结对手 population。
2. **Eligible state**：至少两个 finite legal action；top-1 和 top-2 都是 discard；自己尚未立直；`top1_q - top2_q <= 0.5`。
3. **候选集合**：只允许在 discard→discard 中选择 legal top-2；禁止 discard/reach/pass/chi/pon/kan/agari/ryukyoku 跨语义探索，禁止立直后的探索。
4. **选择规则**：eligible 时以固定 `0.25` 概率选择 top-2，否则选择 top-1。
5. **确定性采样**：使用 SHA-256 对 UTF-8 canonical string `D3_top2_discard_v1|generation_seed|seed_key|seat|kyoku_index|decision_index` 做 hash；字段之间恰好一个 ASCII `|`，字段为十进制 ASCII 且无前导零，字符串末尾无换行、空格或 NUL；取 digest 前 8 bytes 的 little-endian 无符号整数除以 `2^64` 得到 `u`，当且仅当 `u < 0.25` 时探索。不得依赖进程内连续 RNG 状态。
6. **索引与并列规则**：`seat` 是原始 arena seat 的 0-based `0..3`；`kyoku_index` 是每次实际 `start_kyoku` 的 0-based 实例序号，连庄、流局续局和 abortive retry 都产生新序号，不使用东一/东二标签；`decision_index` 是该 K0 玩家在当前 kyoku 中实际需要输出动作的 0-based 计数，每次 `start_kyoku` 重置为 0。top-1/top-2 使用合法且 finite Q 的稳定降序排列，Q 相等时 action id 较小者优先。
7. **预算**：每个 eligible decision 都重新计算 hash；hash 未命中时继续尝试之后的 eligible decision。第一次实际选择 top-2 后当前 kyoku 预算耗尽，之后强制 top-1；hanchan 累计达到 8 次后，之后整个 hanchan 强制 top-1。每次 eligible decision 必须记录 top-1/top-2 action、Q、margin、hash 输入、`u`、实际采样与未采样原因。
8. **native context scope**：Rust `DecisionContext` 明确标记 `primary_action` 与 auxiliary kan guard row；只有 primary action 的 `exploration_allowed=true` 行可以进入 D3 eligibility/hash/budget，auxiliary row 必须原样使用 base action，不写 event、不消费预算。
9. **native lineage**：authoritative smoke/protocol 必须冻结 project Git commit、Mortal source commit、D3 native patch SHA256、实际加载的 `riichi.pyd` SHA256、release build、Python/torch/CUDA/GPU、四个模型 SHA，并要求 project/native worktree clean。
10. **固定 seed/protocol**：25h smoke 使用 `seed_start=1799000`；production 使用 `1800000..1805999` 的 6000 个独立 seed，固定 `seed_key=8192`、`24×250 B250`、random seats、AMP=false。promotion evaluation 继续使用新的不重叠范围。

## Generation gate

authoritative clean 25h smoke 已通过；下一步才是首个 250h B250 production gate。gate 只检查正确性和灾难性行为，不使用 Pt 选择参数：

- smoke：hash 重跑逐 action 一致；探索动作始终 legal 且 100% discard→discard；无 own-riichi 探索；每局/每场预算生效；日志记录完整 exploration event。
- production：250 canonical unique hanchans、250 unique seeds、0 malformed、250 个 K0 perspective、100% explored action 等于当时 parent top-2、100% event 来自 primary action、0 auxiliary-row exploration、0 margin/budget violation。
- 同时记录 realized exploration rate、parent agreement、parent-Q gap、每半庄探索数、phase、shanten/legal-action 分布和宽松 agari/houjuu/fuuro/riichi readout。
- gate 失败即关闭 `D3 generation v1`，不得现场修改阈值或概率后继续同一 experiment ID。

通过 production gate 后才允许生成剩余 5750 个 hanchan；生成完整数据后才可按既定 M0 对照训练，训练 objective/reward/optimizer/network/steps 全部固定。

## 固定变量与 promotion control

当前固定参考为：

- `K0 = 70k` parent；
- `M0_operational_control` 为正式 promotion control；
- objective = `behavior_action_mc`；
- reward = `final_rank_mc`；
- legacy continuation 使用 preserved Adam moments；
- 后续若获准生成，评测仍使用固定的 B250 random-seat protocol，并按完整半庄统计；
- 不在 D3 引入 reviewer/NAGA/4.1b imitation、GRP、legal-mean objective、LR/CQL 网格或架构变化。

## 反自欺规则

- 不按最终顺位、Pt、target 或训练后表现选择探索状态；规则只能依赖生成时可见的 state、合法 mask 和 K0 parent Q。
- 不把 `Q(top-1)-Q(top-2)` 当 ground-truth regret；它只是 parent 内部不确定性代理。
- 不把更低 agreement 自动视为更好；必须同时检查动作语义、parent-Q gap、行为分布和后续同协议强度。
- 不把 M0/D1 的未配对均值相减，作为 D3 的因果证据。
- 生成、训练和评测使用互不重叠、预先固定的 seed 范围，并记录 project/native commit、D3 patch/native binary SHA、模型 SHA、native batch、CUDA/AMP 状态。
