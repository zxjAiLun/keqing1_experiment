# P4-M12：从 U32 续训 32 轮，用父子实战比较决定下一笔预算

**这是本轮的唯一入口。** 冻结于执行之前（design-only），执行记录与结果回填到本文。

## 1. 来源与授权（负责人 2026-09-15 裁定）

- **不批准**上一轮的"梯度噪声探针"；上一轮那份 gap probe（学习曲线 / 参数增量 / 收益均值噪声）
  **不进入下一轮决策依据**，其扩展**到此为止**。
- 已确认**超过 K0 的 U32**；下一笔预算的问题是"**这条训练线能否在 U32 之上继续产生收益**"。
- U32 的天梯接入由 Workbench agent 负责，**不在本实验范围**。上天梯不等于已超过 external。
- 本实验：**U32 → 再做 32 个 cycle → 固定端点 → 与 U32 直接比较**。

被裁定方指出的上一轮错误（记录在案，避免重犯）：曲线缺少流局/立直扣点结算与正式同分排序；
分段斜率未走 `slope_ci()`，且该函数破坏了轮次对应；`2.623−2.459=0.164` 而非报告里的 `0.123`；
"长滞后余弦归零 ⇒ 没有学习信号"不成立（不同轮次策略与访问状态在变、Adam 逐坐标预条件、
32 个增量在滞后 30 只有约两对观测）；`SE(mean G)/|mean G|` 不是策略梯度噪声；
**Gate A 的通过不能被重新解释为"随机游走碰巧有利"，它仍是有效的模型对战证据。**

## 2. 冻结的训练配置

单一 lineage：`hard50k -> C4 -> U32 -> U64`。

**命名规则（先说清，否则路径会读错）**：`U64` 是**模型名**（血缘累计位置，与冻结在
每条 checkpoint 内的 `lineage` 字符串一致），**不是文件名**。checkpoint 文件按**轮次**命名
（`U{cycle}.pth`），于是：

- 本次端点 = `P4-M12_direct_pg_U32_plus32/U32.pth`（Adam step 68，sha `d04c6c8a…`）
- 父 = `P4-M11_direct_pg_C4_plus32/U32.pth`（Adam step 36，sha `511be9ad…`）

两者 **basename 相同、目录不同**；arena 内由标签 `p4m12_u64` / `p4m11_u32` 区分。
P4-M11 两种命名恰好重合（32 轮 → 两处都是 U32），所以这个歧义到本轮才暴露。

`training/mortal/p4m12_direct_pg.py` 的 `assert_only_identity_changed()` 在 import 时校验
"变化的键集合恰等于声明的 13 个"，并对 lr / loss / 对手 / 裁剪这类继承块做双向断言（漏改与误改都会拒绝）。

**预算**：32 cycles × 256 半庄 = **8,192 半庄**，固定，**不根据中间曲线自动延长**。
中间 checkpoint 正常保存，但**不挑"看起来最好"的读点**。

### 3.2 本轮暴露的两个准备缺陷（我的错，已修）

1. **把模型名当路径用**：文档与脚本写了 `U64.pth`，但 checkpoint 按轮次命名，端点实际是
   `U32.pth`。`U64` 本身没错（它是冻结在 32 份 checkpoint 内的 `lineage` 名字，不可改写），
   错的是我把它当文件名。已在 §2 写明命名规则；Gate C 标签用模型名 `p4m12_u64`。
   发现时 Gate C 刚跑 2 分钟，已停掉重跑（旧标签 `p4m12_c32` 的部分产物已删）。
2. **结果文件名写死**：`p4m11_direct_pg.py` 里 `p4m11_result.json` 是字面量，所以本次 run dir
   里躺着一个叫 `p4m11_result.json` 的 P4-M12 汇总（已产生的文件**不改**，作为证据保留）。
   已把该名字改为配置驱动（新增 `result_filename`），并**加宽结构测试**：原来只查
   `keqing.mortal.p4m11`，看不到不带该前缀的文件名。

> **#lesson 负向对照第一次没变红，说明是断言写错了。** 加宽后的测试第一版把字面量收集成**集合**，
> 而配置行本身已经贡献了 `"p4m11_result.json"` 这个名字——所以在调用点再写一遍字面量不会改变集合，
> 对照保持绿色。改成**计数**（每个名字恰好出现 1 次且在配置行）后，三个负向对照（调用点重写
> 结果名 / 重写 schema / 新增未声明字面量）才全部变红。

两个缺陷都不是运行期故障，不影响训练与端点身份；但第 1 条若没发现，Gate C 会直接因找不到
文件而失败，第 2 条会让后续续训的汇总文件继续冒充 P4-M11。

## 4. 评测安排

**第一关 Gate C：候选对父模型（模型名 U64 vs U32），不是再次对 K0。**

对照物是 **P4-M11 那份 `U32_eval_weights.pth`**（sha `3703c943…`），不是本次目录里的同名文件
—— 两份 basename 相同，靠目录与标签区分。

- 冻结协议：原生 `one_vs_three_native.py`，双向各 **1,024 半庄**
  （`--seeds 256 --seed-start 742000 --seed-key 8192 --batch-seeds 8`），
  候选先做 solo、再做 mirror（角色对调、同种子）。
- 评测种子块 **742000–742255**，与训练种子（733000–735047）及 P4-M11 全部分区不相交。
- 裁决：`adjudicate_ovt_gate.py`，指标与阈值沿用既有冻结口径
  （`G=(S−O/3)/2`，`--threshold 2.0`）。
- **通过条件（沿用既有标准）**：两方向候选收益均为正、G 的 95% 区间下界 > 0、G 均值 ≥ +2。
- 完整结束后裁决；**不加局、不换中间 checkpoint**。

**通过后**才跑同预算的 Gate D（U64 vs external，种子块 743000–743255），判断是否接近/越过 EVE 门。
**未通过**则保留 U32 为当前交付模型，结束这次续训，**不自动再加 32 轮**。

> 实际走的是**未通过**分支（见 §5）：Gate C = `not_supported`，因此 **Gate D 不跑**。

## 5. 结果与裁决（2026-09-15 完成）

**第一关 Gate C = `not_supported`。** 追加 32 轮未获得超过 U32 的证据。

| 量 | 均值 | CI95 | seeds+ / 非平局 |
|---|---|---|---|
| S（U64 单挑 vs 3×U32） | −1.8457 | [−5.2734, +1.6271] | 84 / 175 |
| O（U32 单挑 vs 3×U64） | +3.0322 | [−0.0879, +6.0656] | 93 / 160 |
| −O/3（镜像侧候选收益） | −1.0107 | [−2.0219, +0.0293] | 67 / 160 |
| **G = (S − O/3)/2** | **−1.4282** | **[−3.3472, +0.5499]** | 88 / 200 |

冻结条件：`both_directions_positive` **FAIL**、`G_ci_lower_above_zero` **FAIL**、`mean_G_at_least_2.0` **FAIL**（阈值 ≥ +2.0）。

**关键性质：两个方向不是互相矛盾，而是一致指向父模型更强。**

- solo：U64 平均顺位 **2.5137** vs U32 三人组 **2.4954**（U64 更差）
- mirror：U32 平均顺位 **2.4639** vs U64 三人组 **2.5120**（U64 更差）

无论 U64 扮「单挑的 1 座」还是「三人组里的 3 座」，它都略差——两个方向的点估计**同向**（都是 U64 更差）。
本轮是**方向同向、幅度很小**的劣势——G 的 CI 跨 0，平均顺位只差 0.033，不得读成「U64 明显更差」。
区间上界只有 +0.55，已低于预设的 +2 实用收益门槛：不只是「尚未证明改善」，而是数据不支持买到那一级改善。

逐座比率（两方向平均）：平均顺位 2.5129 vs 2.4797（+0.0332）；首位率 24.46% vs 25.70%（−1.24pp）；
四位率 25.94% vs 23.99%（+1.95pp）；和牌率 20.63% vs 21.34%（−0.71pp）；放铳率 12.20% vs 11.99%（+0.21pp）；
副露率 24.81% vs 26.93%（**−2.12pp**）；立直率 22.46% vs 22.35%（+0.11pp）；平均和牌打点 6728.8 vs 6661.3（+67.5）。
即 U64 **减少了副露**、打点微升，但**和牌率降、放铳率升、四位率升**，净效果是顺位变差。

完整性：两个方向各 1,024/1,024 日志、`reused_seed_count=0`、`reused_logs_are_unverified=false`、
`ranks_match_native=true`（native/log/verified 三份 rank_counts 逐项相同）、`data_problems=null`。

**按冻结停机规则执行**：保留 **U32** 为当前交付模型，结束本次续训，**不跑 Gate D、不自动追加局数、不再续 32 轮**。

- 跑前先做 `--dry-run`：验证身份、父恢复、Adam step 与种子派生，再真跑。
- 同一目录内报告与评测有统一入口（本文 + `RESULT.md`）。
- 磁盘：启动时实测 E 盘 311.8 GiB 空闲；32 轮体量与上轮同量级。

## 9. 不得写入的表述

- 不写"U64 已超过 external"：Gate C 只回答"是否强于 U32"，EVE 门要 Gate D 才知道。本轮 Gate C 未通过，
  **Gate D 没有跑**，因此本轮对 external 差距**没有任何新证据**。
- 不把 Gate C 的小幅负结果写成"再训练让模型变差了"：G 的 CI **跨 0**（不能确认变弱），
  同时**区间上界 +0.55 低于 +2 门槛**（数据也不支持买到那一级改善）。两条都是事实，不可只取其一。
  正确表述是"**未检出**超过 U32 的收益"，而不是"U64 明确更弱"。
- 不把"U64 副露减少"当作优点单独表述：它的和牌率同时下降、四位率上升，净效果是顺位变差。
- 不把 Gate A/B 的结论改写成机制解释。
- 不据中间轮次的任何遥测挑读点或宣布趋势。
