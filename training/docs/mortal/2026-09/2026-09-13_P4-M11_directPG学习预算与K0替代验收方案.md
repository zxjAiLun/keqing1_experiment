# P4-M11：direct PG 学习预算、K0 实用门与 external EVE 门

日期：2026-09-13。负责人方向决定与本地执行交接。修订：两级目标对齐；训练配方与训练预算不变，external 从条件差距测量升级为正式 Gate B。

## 1. 目标与当前事实

本轮研究问题：给已运行的 direct-PG 闭环一次明显更充分的连续学习机会，判断 project-owned 模型能否先超过 K0_70k 的历史普通训练水位，再挑战 external_mortal 所代表的目标 EVE 强度区域。战胜 K0 是第一道实用门，不是项目研究成功的终点。

| 对象 | 固定角色与口径 | 不能声称 |
| --- | --- | --- |
| K0_70k | 历史 conventional-training reference / 当前消费参考；人类牌谱与常规 Mortal 训练路线的 observed high-water mark | 已证明的训练范式天花板、战胜它即完成 EVE 目标 |
| external_mortal | strong external reference / EVE gate proxy；可实际对战的目标强度参考，同时也是本轮固定训练对手 | 对整个 EVE 生态的通用等级认证 |
| Mortal 3.0 | 用户的体感参照 | 没有权重和直接对战证据，不建立与 external 的已验证等级对应 |

截至本计划：K0 是唯一正式 play/review 消费参考；hard50k 对 K0 未检出明确差异，C4 没有直接对 K0 的替代验收。P4-M10 not_supported 及所有旧实验停止规则保持原样，不能称已有 >K0 模型。文档不再把 K0 简称为 baseline；下文 baseline=0 专指策略梯度的回报基线，不是模型角色。

本轮只有 `hard50k → C4 → U32` 一条 lineage。即使两个门都通过，也只说明这条训练过程产出了达到目标的 checkpoint，并强力支持继续投入该路线；不孤立证明数据量、配方、机制或随机性各自的贡献，不证明稳定可复现地胜出。独立训练重复留待出现值得复现的结果后再决策，本轮不启动多 seed 训练。

P4-M11 是新的单候选学习预算，不是重开 P4-M10，不修改旧训练身份、旧预算或旧结论。用户已认可继续 direct PG，由负责人主动定方案，本地 agent 实现与执行，云端做聚焦代码 review，负责人在结果完成或实质 blocker 时接手。不需要每个正常阶段重新请示。

## 2. 路线决定及预算依据

从 P4-M10 的固定末端 C4 继续，而非挑选 C1-C3，不重新跑 hard50k 到 C4。

只增加学习周期，保留已运行的目标、模型、采样与优化器配方。理由是闭环可用、实际策略已有小幅移动、没有崩溃证据；并非小位移证明延长必然有效。此次投入检验更大预算的端点能否满足实际替代目标，不声称辨明所有机制或保证收敛。

- 新增 32 cycles，每轮 64 seed × 四座轮换 = 256 半庄。
- 新增 8,192 半庄、32 次 optimizer update；全谱系累计 36 次 PG update。
- 只评新实验 U32 末端。U08/U16/U24 不做实战，不按 telemetry 选点。
- 不在 U08/U16 再设置负责人批准门；正常且安全则自动完成 U32。
- 预算来自已测四轮 1,886.9 秒：32 轮线性外推约 4.2 小时；计划训练 4–5 小时。Gate A 评测2,048半庄；仅Gate A通过后追加已预定的Gate B评测2,048半庄，评测合计上限4,096半庄。依历史吞吐估计：只运行Gate A的全流程约6–7小时；两门及工程检查全流程约7–9小时。后者是此次新增的条件预算，不是训练预算增加，性能变化可能使估计失准。
- 自动运行时间上限：训练相关活跃运行累计 6 小时；超过则安全暂停，不把部分端点当 U32，不擅自增加预算或宣布失败。硬件/实现中断不是科学负结果。

## 6. Sequential two-gate evaluation：固定 U32，不更换权重

### Gate A — K0 practical replacement gate

历史训练/当前消费参考：`artifacts/mortal_training/checkpoints/mortal_default_70k_promoted_candidate.pth`。

K0 SHA256（本轮只读实测）：`6c0e70058644e02671440ddf7dd2b41c637ae7c2132c9154595593ab690d49e0`。

训练完成后自动进行固定评测，不因训练 return/loss/flip 大小取消或增减样本：

- solo方向：U32 单挑 vs 3×K0，1,024半庄。
- mirror方向：K0 单挑 vs 3×U32，1,024半庄。
- 两方向均 seed 740000–740255，key8192，native OneVsThree，batch-seeds8；每seed四座轮换。greedy部署模式，V1 FP32及既有guard语义。

- 完整日志重算逐seed名次与原生结果一致，checkpoint/运行身份必须绑定；resume不得混入别的权重/seed/环境。

### 两个门共用的单门 primary endpoint（单位一致，逐门独立裁决）

对该门的参考模型R和每个seed i：S_i是四次轮换中的U32单挑平均rank pt；O_i是R单挑平均rank pt。Gate A中R=K0，Gate B中R=external。

统一为每个候选座位单位：镜像候选收益为 `-O_i/3`。预先定义对两种桌面组成等权的协议指标：

`G_i = (S_i - O_i/3)/2`。

每个门对自己的256个seed块同时重采样两方向（保留配对），5,000次bootstrap，统计seed固定20260913，报告mean(G)及双侧95% percentile CI；同时分别报告S、O原单位、-O/3及各方向CI。两门不混合seed、不拼接成一个总体CI。不能将其叫通用Elo或任意对手下的强度。

单门PASS需要同时满足：

1. mean(S)>0 且 mean(-O/3)>0；
2. G 的95% CI下界>0；
3. mean(G)>=+2.0 rank pt/候选座位/半庄。

第3项是预设实用收益阈值，两门一致；不是基于本轮结果选择的数字。该协议是针对指定参考对手的筛查，不证明所有阵容下均优于R，也不孤立归因PG相对C4/hard50k的因果增益。本轮不新增parent对照以追求机制归因。Gate A、Gate B按预定顺序执行，不能因不满意某一门结果改变指标、阈值或样本数。

Gate A条件未满足：`practical_gate=not_supported`，`eve_gate=not_run`。本轮没有交付被证据支持为强于历史普通训练参考的模型；不替代K0，不运行Gate B，不挑中间checkpoint、不追加seed、不自动调参/续训。不能写成已证明U32不强于K0或PG理论失败。

不得将K0替代候选登记为“项目最终成功”，也不得因EVE门未通过就把真实的实用进展抹去。

## 8. 完成与交接方式

本地 agent：实现小范围增量→聚焦验证与资源生命周期检查→提交并交云端review→review无阻塞后完成已批准训练、Gate A及条件Gate B/消费交付→结果落盘→负责人结果review。按用户既有工作流 commit+push；任何日志/权重等大artifact不误提交。

最终报告首先分别回答三个问题：是否超过历史K0参考、是否通过external EVE门、能否在play/review选择。分别登记 `practical_gate`、`eve_gate`、`consumer_acceptance`，不能以一个笼统的PASS合并。再附训练累计updates/半庄、真实墙钟/磁盘峰值、安全事件、每个已执行门的完整双向统计、身份和消费适配边界。不再用“链路跑通/测试数量”替代强度结论。

本计划落盘不意味着训练已经启动；负责人本轮不写trainer、不占用GPU、不修改workbench默认、不改旧实验裁决。计划本身即下一阶段方向与预算交接，不再要求用户重复提出“请制定具体方案”。
