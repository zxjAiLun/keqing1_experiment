## 第 2 轮：2026-09-13 执行层缺陷修复（review REJECT 后，训练仍未启动）

**2026-09-13 执行层缺陷修复（review REJECT 后，训练仍未启动）**：① 资源保护改为运行期生效——新增 `ResourceWatchdog` 守护线程按 `sample_interval_seconds` 在 cycle 运行期间采样并逐条落盘 `resource_samples.jsonl`，样本折叠进安全暂停/硬停状态机；关键指标缺失**视为违约**（`preflight_violations({})` 不再返回空）；硬停只对**读得到的**低于硬停阈值的值生效，探针读不到只升级为安全暂停；cycle 内三处安全点均 check。② resume 只读 checkpoint **自身记录**并与本进程比较（recipe / environment / lineage parent 路径+SHA / cycle / completed_cycles / Adam step），返回值携带记录的 parent 而非当前配置；新增 `environment_fingerprint` 绑定 interpreter/python/torch/cuda_available/**native 二进制 sha 集合**，native 构建变化即拒绝恢复；采集复用 manifest 补齐 champion SHA 与路径、完整采样配置、seed 段/seed key/sampling_seed/splits_per_seed/return_baseline/native sha/interpreter。③ 每次采集写入不可变的 `cycle{N}/attempt{K}/`（绝不复用已存在 attempt），采集产物与 manifest 均在 attempt 目录内，cycle 根目录只剩确定性的 `collection_weights.pth`；损坏完成标记与缺失 checkpoint 直接报错不再跳过；所有 torch 写入统一走 `_save_torch_atomic`（模块内不再有裸 `torch.save`）。④ 官方入口删除 `--cycles`/`--seeds-per-cycle`，每轮 seed 数恒取冻结配置；诊断必须走 `--diagnostic-cycles` 并写 `p4m11_diagnostic_result.json`；完成由纯函数 `completion_status()` 锁定为 U32/Adam step 36/parent 未改/非诊断，否则 `evaluation_endpoint = null`；六小时计时改为 heartbeat 记账，中断的尝试也计入。验证：聚焦测试 **61 项通过**（新增 26 项负向）；`verify_p4m11_review_fixes.py` **19/19**；相关冻结测试合计 **146 项通过**；仓库默认 allowlist 套件 **291 passed / 5 pre-existing failures**（与基线一致；P4-M11/M10/M9 测试文件按既有惯例不在该 allowlist 内）。复现脚本首次运行 2c FAIL，暴露环境指纹只读 `native_binaries` 而伪造的顶层 `native_sha256` 被忽略，已改为伪造真实字段并补测试。**未启动训练**：未采集、未 step、未产生 U32、未跑门、未碰 workbench 默认。

## 第 3 轮：2026-09-13 第二轮执行缺口修复（review 复审后，训练仍未启动）

**2026-09-13 第二轮执行缺口修复（review 复审后，训练仍未启动）**：① 严重压力计数不再累计不连续样本 —— `observe(..., advance=True)` 无条件喂入两个 guard（健康样本真正清零），`advance=False` 用于阶段边界快照（记录并落盘但不推进计数，守卫已触发时 `check()` 仍会报），`record_sample()` 一律 advance=False。② 停机时间不再计入六小时预算 —— heartbeat 新增 `elapsed_seconds` 并由 in-cycle watchdog 的 `on_tick` 每次定时采样刷新；`accumulated_active_seconds()` 只计 `active_seconds_at_start + elapsed_seconds`（最后一次心跳），不计进程死亡后的间隔；`end_active_cycle()` 因进程全程存活而按 `now - started_unix` 足额计入（崩溃最多少计一个刷新间隔，隔夜等待零计费）。③ 执行配方与记录配方不再可能漂移 —— 新增 `assert_recipe_arguments()`，官方入口只在覆盖值等于批准值时接受 `--champion`/`--challenger-label`/`--champion-label`/`--micro-batch`/`--grad-clip`，任一偏离即拒绝；`P4M11_CONFIG` 新增 `champion_sha256`（冻结 external SHA）与两个 label，main 额外校验实际 champion 文件哈希；`training_contract()` 与 checkpoint payload 新增 `opponent`/`opponent_sha256`，`load_committed_checkpoint()` 读并校验记录的对手，缺失或不符即拒绝恢复。验证：聚焦测试 **61 → 84 项通过**（新增 23 项）；`verify_p4m11_review_fixes.py` **19 → 25/25**（新增 5a/5b/6a/6b/7a/7b）；相关冻结测试合计 **174 项通过**；仓库默认 allowlist 套件 **291 passed / 5 pre-existing failures**（与基线一致）；`--dry-run`（mandated 解释器）preflight 空、C4 cycle 4 / Adam step 4.0 非 fresh、32 轮、E 盘 490.5 GiB；真实 CLI `--micro-batch 256` 被拒。首次运行中验证脚本 4d 与既有测试 `test_accumulated_active_seconds_counts_and_commits_attempt_time` 同时失败——它们断言的是被本轮修正的旧语义，已改按新契约。**未启动训练**：未采集、未 step、未产生 U32、未跑门、未碰 workbench 默认；下一步已定：正式 U01/U02 观察资源释放，健康即续至 U32。

## 第 4 轮：2026-09-13 第三轮收口（二次复审后，训练仍未启动）

**2026-09-13 第三轮收口（二次复审后，训练仍未启动）**：① collection manifest 的 `complete=true` 移到 `hanchan_returns_from_logs` + `assert_collection_complete` PASS 之后原子写入——因此 manifest 存在即等价于「authoritative log completeness 已通过」，残缺 logs 的 attempt 没有 manifest、永不被复用，重采落到新 attempt 目录，不再出现「坏 attempt 被反复复用、永不产生 attempt2」。② `train_cycle()` 不再写完成标记，改为返回 `commit_marker` payload；`main()` 固定顺序为 **append cycles.jsonl（flush+fsync）→ 最后写 `Ux.done.json`**，消除「checkpoint+marker 存在但 cycles.jsonl 无该轮」的可达状态；同时收紧 `committed_cycles()`：marker 文件名必须与 `completed_cycles` 一致（`U2.done.json` 必须声明 2），且 committed set 必须从 U1 起连续，缺口即报错。③ fresh start 钉死环境：新增 `assert_pinned_device()` 无条件要求 device==cuda 且 CUDA 可用（删除 `--require-cuda`，不再存在 CPU fallback）；新增 `assert_fresh_start_environment()` 在 `last_committed==0` 时额外钉死 `sys.executable` == 预注册的 keqing1/.venv-win 解释器，且 native 二进制集合必须含预注册 V1 `19bb181e…`（resume 由 `load_committed_checkpoint` 的环境比较负责）。④ `--diagnostic-cycles` 整体删除（含 `p4m11_diagnostic_result.json` 与 `completion_status` 的 `diagnostic` 参数），因为它仍会向正式 output dir 写 `U1.pth`/`U1.done.json`。验证：聚焦测试 **84 → 90 项通过**（新增 6 项负向）；`verify_p4m11_review_fixes.py` **25/25**（规模未扩）；相关冻结测试 **180 项通过**；allowlist 套件 **291 passed / 5 pre-existing failures** 不变；dry-run（mandated 解释器）PASS，而同一个 dry-run 用错误 CPU 解释器被 **REFUSED**（`refusing to train without the pinned GPU: device is 'cpu', not 'cuda'`）。**未启动训练**：未采集、未 step、未产生 U32、未跑门、未碰 workbench 默认。
