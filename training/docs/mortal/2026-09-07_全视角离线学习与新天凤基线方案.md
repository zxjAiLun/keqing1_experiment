## 3. “看到错手及惩罚”的想法成立，但实现有三层区别

### 3.1 全视角有合理价值

全视角能增加实际动作覆盖、落后/领先状态、进攻/防守及不同后续策略的样本。只保留强者动作也有局限：可能缺少弱行为附近的价值信息。因此没有证据支持直接丢掉其他三家的数据。

但“其他玩家”不等于“错误示范”，“高手”也不等于每一手最优；采集玩家身份、当时段位与真实动作质量是不同字段。次优行为支持也只覆盖真实观察过的局面/动作，不等于拥有所有动作的反事实标签。

### 3.2 负结果不是动作错误标签

需要区分三种监督：

| 监督对象 | 牌谱能直接提供吗 | 含义 |
| --- | --- | --- |
| 实际行为 a | 能 | 该玩家当时选择了什么 |
| 已发生的局/半庄结果 | 能 | 在该行动及之后其他行动、摸牌、对手行为下发生的结果 |
| 同状态下 a 相对 b 的期望损失 | 不能直接提供 | 要比较未发生的替代路径，需要额外估计或交互 |

例如“这一手放铳”不能单独证明它的期望收益低于弃和；也可能有正确押牌却遇到坏结果。反过来，“这场一位”也不能证明前面的每一手正确。只凭结果筛掉输牌局，会破坏用户希望保留的覆盖，也可能放大幸存者偏差。

K0 旧奖励实际是 GRP 在局边界上的期望顺位点变化，最后接真实最终顺位；旧 loader 将当前局的奖励用于该局决策。后来 M0 的 final_rank_mc 才将最终半庄顺位回报用于各决策。这两者都不是独立标注的“逐手错误惩罚”。

### 3.3 当前损失同时有结果拟合和行为偏好

根据当前 `training/mortal/objective.py` 及历史 runner，Q 输出空间中的单行简化形式：

`L = 0.5*(Q(s,a)-y)^2 + alpha*(logsumexp(Q_legal)-Q(s,a)) + auxiliary`

第一项把实际动作 Q 拉向观测目标。第二项不读取该行 reward；在输出空间中，它相对提高已选动作、压低未选动作。对参数的最终影响还受网络共享表示、其他样本、优化器与辅助损失影响。

以两个合法动作、Q=[0,0]、已选 a=0、观测目标 y=-1、alpha=5 为纯数学例子：

- 回归项对 Q 的梯度 `[+1,0]`，梯度下降会降低已选动作值。
- 加权 CQL 梯度 `[-2.5,+2.5]`，梯度下降会提高已选动作的相对偏好。
- 两项合计 `[-1.5,+2.5]`，该局部例子并不会因为目标为负就自动减少已选动作偏好。

本次用 CPU autograd 核验了上述例子；它不是训练实验，不代表实际数据中的平均梯度，也不证明 alpha=5 太大。

所以更准确的理解是：当前路线利用多质量行为数据，在回报回归与行为支持约束之间学习；不是给错手贴标签后直接惩罚。原始 [CQL 论文](https://arxiv.org/abs/2006.04779) 主要针对离线分布外动作的价值高估，不是一个错手检测器。论文的 Bellman 学习分析也不能原封不动当成本项目 MC 回归实现的保证。

这不是新发现“关掉 CQL 就能好”的理由：项目 C1/C3 已证明机制交互与绝对强度晋级不同。保持既有停止边界，不以这个解释重开 CQL sweep、F1/F2/F3 或单步反事实路线。

- 首个基线保持普通逐决策训练，不同时引入新重采样/质量权重。分玩家来源、规则与阶段只做描述性覆盖报告，避免悄悄改变采样分布。

## 5. 训练与评测：新母体，不重复建设已有工程

### 复用已有能力

当前 `training/run_mortal_dqn_offline.py` 已保存 `data_stream`、Python/Torch/CUDA RNG；恢复时重建数据顺序、跳过已交付 batches 并核查 RNG。缺失游标的 legacy checkpoint 默认拒绝恢复，需明确允许才重放前缀。

因此不能把 4 月旧 runner 的问题描述成“当前项目还没有恢复机制”。应在新数据集和实际 Windows worker 设置下验证现有实现，而不是重写整个训练器。当前实现重建时会读取旧前缀，语义上跳过而非重新训练；这可能有恢复耗时，需测量后再决定是否优化。

现有 `mainline_dataloader.py` 支持 all-seats、按文件视角和显式 `mortal_grp_delta_pt`；`prepare_grp_v1.py` 有内容规范化 hash 及原生解析核验，可复用思路，但它的默认来源是历史合成牌谱，不能直接当新天凤入口运行。

### 首个从零基线建议

- 以 192×40 Mortal 架构、46 动作和原生编码为起点，fresh random Brain/DQN/Aux/optimizer，从 0 计步；K0 不作初始化，只作对照。
- 优先建立接近 K0 语义的“新天凤全视角 + 独立训练并冻结的 GRP delta-Pt + DQN/CQL/next-rank”基线。新 GRP 只使用训练 split 拟合，验证选模，最终保留集不用于调参。
- 明确配置 `[reward].mode=mortal_grp_delta_pt`，不能把当前默认 final_rank_mc 不经说明带入所谓旧路线重建。是否采用此基线、总步数和超参数仍需在执行前形成新合同；不是恢复旧 R0，更不是重开已停止的 GRP 参数网格。
- 数据更新、去重、游标修复与新初始化意味着这是一个新的可靠基线，不是对过去 K0 的逐位复现。也不能把其结果解释为单一因素的因果实验。
- 先验证小批量数值、恢复数据身份、loss/gradient 有限性，再按实测吞吐和样本量冻结训练预算/检查点，不立刻开大规模网格或多 seed 长跑。
- 增设连续 N 步与 N1+resume+N2 的对照测试；根据平台确定性能力分别验证行身份、optimizer step、RNG/BN/参数一致性或预注册容差，不宣称任意 CUDA 环境天然 bit-exact。

### 强度门

- 训练与独立验证曲线用于诊断；和牌/放铳/副露率用于解释风格，均不能替代最终强度裁决。
- 开发集负责筛 checkpoint，最终游戏种子独立冻结；对 K0 的 Pt 差值与 CI 是首要成功门，对 external 的差距单独报告，避免只适应 K0。
- 可以先完成一条预注册学习曲线再决定是否值得多 seed 确认；单 seed 好看不能晋级为可复现强模型。
- 不要求人工看完每一局。机器负责完整日志、规则与统计审计；人工只抽查预先定义的场景和异常。
- K0 及必要历史对照、external 的文件 SHA 保留不变；不修改 T1 等旧裁决，不加旧评测局数。
